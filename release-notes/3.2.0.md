# TPS Controller 3.2.0

Recurring feeds can now create active occurrences and just one upcoming occurrence
per series instead of materializing their whole import window. Select **Calendar
rules → Configure a feed → Recurring event notes → Current + next occurrence**.
The existing sync interval advances it; no new timer, local recurrence expansion,
watcher, cache or repair loop is introduced.

- Existing feeds keep **All occurrences in import window** by default.
- Past notes remain. Existing future notes continue receiving source updates and
  configured cancellation/reschedule handling. This setting does not prune them.
- Canceled unowned recurrences cannot occupy the next slot. Full feed presence
  remains available for missing-event checks, even for unselected occurrences.
- The explicit 14-day backfill command can still import historical occurrences.
- **Import horizon (days)** configures the shared lookahead: default 60, valid
  integers 1–3660. A next occurrence must be returned inside the query window.
- Proven older recurring source revisions stop next-mode sync before writing.
  All-occurrences mode retains its existing stale-revision behavior.
- Property keys, template classifications, lifecycle status values and source
  identities remain configured through their existing owners.

This is an additive minor release. Minimum Obsidian remains **1.12.3**. No note or
settings migration runs on upgrade. The existing settings destination hub and
native controls/mobile CSS are preserved.

## Validation and limits

All **767 declared checks passed**, with zero failures or skips; this includes the
exact historical notification reference, 16 new calendar regressions, settings
coverage, and complete mobile-module loading. TypeScript, full tests and the
mandatory separate production build passed. Shipped artifacts were deployed only
to **Obsidian Plugin Test Vault** and Controller was reloaded by manifest ID.

The installed class was compared using the same memory-only 20-occurrence source:
3.1.8 created 20 notes; 3.2.0 next mode created one. Repeated sync and repeated
cancellation made zero writes. A synthetic ended/canceled occurrence advanced one
new note and kept history. First-pass template reads stayed one; Controller added
zero inventories/listeners. These counts use synthetic provider/GCM/file
boundaries, not physical source notes or production latency measurements.

The actual native settings picker selected next on a disabled synthetic feed. A
120-day horizon saved, while an invalid 0 draft did not. The isolated settings
facade was removed; real Controller data remained byte-identical. All eight active
TPS consumers stayed enabled. Pre-existing calendar identity-conflict fixtures
blocked real-file creation in the full test-vault snapshot; safeguards were not
bypassed. Real-provider end-to-end and physical iPhone acceptance remain device
rollout tests, not claims made from these checks.

The source-backed [TishOS app plan](https://github.com/ZachTish/tps-controller/blob/3.2.0/docs/tishos-app-recurring-import-plan.md)
covers the app's complete observed batch, frozen creation selection, configurable
window validation and existing Controller overlap guard. No app code was changed.
This option does not make simultaneous EventKit/ICS importers safe.

**Tested in the test vault and ready for the user's BRAT pull.** Production
installation and enabling the mode on production feeds remain separate steps.
