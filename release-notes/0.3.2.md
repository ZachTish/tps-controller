# TPS Controller 0.3.2

This patch aligns the tagged source with the already tested reminder-discovery efficiency improvement that was present in the preceding feature-release artifact.

## What changed

- Reminder discovery now normalizes each own frontmatter key and checks it directly against the existing normalized reminder-property set.
- It no longer allocates and populates a second Set for every scanned Markdown file.
- The optimized `main.js` is byte-identical to the public 0.3.1 feature artifact; 0.3.2 makes the tagged source and release metadata accurately describe those shipped bytes.

## Compatibility and migration

- This is a backward-compatible patch release.
- Candidate membership, own-key semantics, key normalization, file ordering, inherited-key exclusion, inline reminder fallback reads, settings, and stored reminder state are unchanged.
- No migration or settings change is required.
- Minimum supported Obsidian version: 1.12.0.

## Validation

- All 124 declared tests passed at version 0.3.2. Focused coverage verifies whitespace/case normalization, own-property handling, inline fallback reads, candidate order, and the absence of a per-file key collection.
- The required separate production-mode build passed and deployed byte-identical source/runtime artifacts to `Obsidian Plugin Test Vault`.
- Obsidian 1.12.7 was reloaded with **Reload app without saving** in passive User mode. The Controller notification sidebar opened normally and no outbound automation was enabled.
- Runtime-owned `data.json` retained SHA-256 `6cac531dcd6d0b6971dc4c14ccc7dbc0b940c72b3f87f4a2dff8663129fa75d0`.
- Production was not accessed. This release is ready for the user's BRAT pull.

## Known limitations

- This removes a bounded per-file allocation; it deliberately does not introduce a persistent candidate index or cache.
- Performance gains scale with frontmatter scan volume and are intentionally not claimed for small vaults.
