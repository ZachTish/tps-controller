# TPS Controller 2.4.1

Extended calendar-sync testing found and fixed timezone errors and unnecessary filename changes. This backward-compatible patch improves correctness and reduces repeat file renames; no settings or defaults change.

## Fixes

- Correct spring/fall DST conversion, including the first repeated hour and the pre-gap interpretation of an explicit nonexistent time. Cover both IANA zones and provider-embedded VTIMEZONE definitions, including UTC recurrence exceptions.
- Respect a different timezone on DTEND. Recurrences retain DTEND's exact duration; DURATION distinguishes nominal days/weeks from elapsed hours/minutes/seconds.
- Reject an unresolved explicit timezone instead of silently using the device's local time.
- Keep valid numbered filename suffixes after a sibling event renames.
- Preserve a filename settled by the vault's filename automation when the imported title and schedule have not changed. External title/schedule changes still request a readable name, and GCM still owns root/layout resolution.

## Validation

The full Controller suite passed **567 tests**, with **3 existing optional comparison skips** and zero failures. The focused parser/native-record suites have 115 tests. Expanded coverage includes 100 seeded shuffles of 25 recurring series, a 120-operation lifecycle replay with 24 failed downloads and manual edits, interruption after each of six writes in a three-event reschedule, four device timezones, mixed/embedded timezone cases, HTTP/network/timeout/conflicting-feed failures, and 2,600 zoned occurrences.

TypeScript and the mandatory separate production build passed. The final version was deployed and reloaded only in **Obsidian Plugin Test Vault**. Real parser/Controller/GCM tests with six colliding events verified exact byte/path stability over three repeat syncs, failed-feed safety under archive policy, one replacement on an external move, old/current property actions, and stale-revision protection. The first real-vault runs detected the filename-automation conflict; the final patched run passed. GCM discovery was scoped to synthetic files because historical QA fixtures intentionally contain identity conflicts. Existing filename automation remained active. All fixtures were archived; Controller/GCM settings hashes stayed unchanged and outbound automation remained disabled.

[Full validation matrix and limits](https://github.com/ZachTish/tps-controller/blob/2.4.1/docs/calendar-sync-validation.md).

## Upgrade notes and limits

Minimum Obsidian remains **1.12.3**. Property actions and retained history remain native-event-note features from 2.4.0. The first sync may correct affected previously imported times; if keep-old history is enabled, a correction can retain an additional historical note. Existing duplicates are not merged or deleted. Changed provider UIDs or rewritten master schedules without original recurrence identifiers remain ambiguous. Floating events intentionally follow the device timezone. Use one designated writer.

These tests used synthetic feeds; live-provider and physical iPhone/iCloud acceptance remain separate. This release does not move synchronization into the TishOS app.

**Tested in the test vault and ready for the user's manual BRAT pull. Production was not accessed or updated.** Exact tag: `2.4.1`. Standard styles.css contains all UI styles; styles-ui.css is optional compatibility material.
