# 0.10.3

TPS Controller now publishes phone-local TishOS reminder schedules only from a verified metadata snapshot and exposes enough per-device state to explain an empty or pending queue.

- Local/no-relay acceptance is explicit: a separately paired iPhone or iPad Obsidian instance publishes its own Controller-rule schedule directly to TishOS when **Enable Reminders** and **Notification Service → TishOS** are selected. Mac relay and Controller role are not prerequisites.
- MetadataCache's `resolved` event is registered before settings loading can yield. Layout readiness alone never authorizes an empty schedule or pairing callback. A late-enable fallback requires a complete non-empty Markdown metadata snapshot, including non-null empty CachedMetadata objects for plain indexed notes.
- A metadata-resolved refresh that joined a pre-index single-flight refresh immediately retries after that operation settles, so the exact post-index schedule is verified before pairing returns to TishOS.
- Missing-provider migrations choose TishOS on mobile and User-role devices; only a persisted desktop Controller retains the historic ntfy fallback. Explicit TishOS/ntfy choices remain authoritative.
- Notifications and Settings expose master/provider truth plus each paired client's schedule state, projected item count, last verified time, and pending reason. Pending state is cleared on revoke and stop; per-client counts are not added together.
- Master-off keeps both the Controller audit list and the signed native projection empty. ntfy status now distinguishes the actual desktop Controller route from mobile/User devices where ntfy cannot deliver locally.
- The schedule contract, command contract, signatures, secrets, reminder rules, task/note content, and minimum Obsidian version are unchanged.

Validation passed the 116 focused provider/reminder/bridge checks with three preserved historical reminder-comparison skips, all 20 package-declared test files, TypeScript, and the required separate production-mode build. The complete suite deployed byte-changed release artifacts only to the isolated test runtime; the standalone build then reported `[runtime-deploy] target=test ... unchanged`.

Obsidian 1.13.7 reloaded only **Obsidian Plugin Test Vault** through the developer plugin-reload command and loaded TPS Controller 0.10.3. The live audit surface rendered the current safe synthetic state truthfully: User role + explicit ntfy selection + no local ntfy route + empty TishOS schedule. No real pairing credential or production data was copied into the test vault, so physical-iPhone delivery remains the post-release acceptance check. Source and test-runtime release artifacts are byte-identical, no staging/backup artifact remains, and runtime-owned `data.json` and `.hotreload` retained their exact pre-build hashes.

Runtime metadata evidence used two synthetic test-vault notes: a metadata-free plain note returned non-null CachedMetadata with `sections`; a frontmatter task note returned `sections`, `listItems`, and `frontmatter`. Both fixtures were moved from test-vault `Inbox` to `_archive` after verification.
