# TPS Controller 0.1.3

TPS Controller now leaves Notebook Navigator file selection and file-opening behavior to Notebook Navigator and Obsidian instead of globally replacing workspace leaf APIs.

## User-visible changes

- Controller no longer redirects Notebook Navigator same-tab requests into newly focused tabs.
- Cmd/Ctrl and Shift multi-selection and drag preparation no longer enter Controller's timing-based redirect window.
- Controller-owned commands, reminder navigation, calendar sync, and other explicit file-opening routes are unchanged.

## Reliability and compatibility

- Removed Controller replacements of `Workspace.getLeaf`, `WorkspaceLeaf.openFile`, and `WorkspaceLeaf.setViewState`, along with document-wide interaction listeners and stack/timing ownership heuristics.
- Added a whole-TypeScript-source regression guard against restoring the retired patch.
- TPS Global Context Menu 1.3.1 supplies the matching Daily Note Home selection-only guard; both releases together remove the forced-tab and Home-takeover layers.
- Minimum supported Obsidian version: 1.12.0.
- No settings or data migration is required.

## Validation

- Focused Notebook Navigator isolation regression: 1/1.
- Scoped release suite: 78/78.
- The required separate production-mode build passed after the documentation update and left the final test runtime current.
- Source artifacts matched the isolated test runtime byte-for-byte.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. Notebook Navigator opened the requested Daily Note without Controller creating or repeatedly focusing a replacement tab.

## Known limitations

- GCM 1.3.1 is required to prevent its Daily Note Home observer from converting Notebook Navigator selection-only `file-open` events. Controller 0.1.3 removes Controller's separate forced-tab behavior.
- GitHub Actions builds remain unavailable because this contained source layout imports the adjacent shared `Plugin Development/deploy-runtime.mjs`.
