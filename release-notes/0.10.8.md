# 0.10.8

TPS Controller now actively invalidates an iPhone's already-scheduled Apple notification queue when a still-pending reminder series is removed on that same iPhone.

- After publishing the replacement signed schedule, mobile Controller opens one fixed `tishos://controller-refresh?v=1` handoff only when a prior authenticated series had a future occurrence and the new schedule removes that series.
- TishOS treats the route only as a refresh request. It independently verifies the replacement schedule with the existing per-device credential before cancelling any Apple request; the URL carries no vault path, reminder identity, credential, or mutation authority.
- Repeat advancement within the same series, unchanged schedules, already-expired one-shot reminders, publication failures, desktop clients, and ordinary additions do not trigger the handoff.
- The existing 64-occurrence cancellable queue remains intact, so background repeat coverage is preserved while same-device task deletion, completion, filtering, or another terminal removal can cancel its remaining queued occurrences without waiting for a manual TishOS launch.
- Notification-action version 2 from Controller 0.10.7 remains unchanged and compatible.
