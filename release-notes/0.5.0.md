# TPS Controller 0.5.0

Released: 2026-08-14

## Native TishOS Shortcuts command bridge

- TPS Controller now supplies a per-device, searchable catalog of the actual commands registered in the exact current Obsidian vault for TishOS's native **Run Obsidian Command** Shortcuts action. The catalog updates automatically and removes the separate Get/Purge command-cache workflow required by Actions for Obsidian.
- Pairing starts only from a linked TishOS vault and requires explicit confirmation in Obsidian. The Controller stores bounded device metadata in Obsidian's vault-specific local storage, retains the random 256-bit peer credential only through SecretStorage, and publishes one signed hidden catalog per client.
- Each run is independently authorized with exact native and asserted vault names, current client identity, command ID/name digest, a fresh request UUID and issuance time, HMAC-SHA256, persistent replay protection, and a fresh current-registry lookup before one no-argument dispatch.
- Controller remains role-agnostic for this bridge. A Mac and iPhone use different client identities and secrets, so a catalog copied through vault sync grants no authority to another device.

## Reliability, privacy, and limits

- Catalog publication uses a verified staged file plus recoverable same-directory backup and preserves an existing valid catalog across registry, cryptography, size, or filesystem failures. It rewrites only when the semantic command set or publisher identity changes.
- Pairing waits one short host-transition window before presenting its confirmation. An external pairing URL received while Obsidian Settings is open therefore closes Settings and then presents the authorization prompt instead of letting the Settings teardown discard it.
- Pairing has its own single bounded lane: exact duplicate requests coalesce, different concurrent prompts fail busy, and an unanswered unauthenticated prompt cannot delay signed runs or signed/settings revocation. Plugin stop invalidates post-modal approval and queued execution while draining only finite authenticated work.
- Replay consumption is fail-closed even when Obsidian's vault-local save API silently drops a write: Controller reads the exact client/request/timestamp entry back before command execution. An unconfirmed replay write executes nothing and remains safely retryable.
- Signed and settings-driven revocation persist a vault-local tombstone before waiting for active publication, immediately suppress execution, callbacks, status, and republishing, then independently clear pairing state, replay entries, the SecretStorage value, and target/staging/backup artifacts. Incomplete cleanup retries after reload without restoring authority.
- The catalog is bounded to 1 MiB and 4,096 unique unambiguous commands. It contains command IDs, display names, publisher/client identity, digests, and a signature—not the secret, note content, plugin settings, arguments, or execution history.
- Version 1 has no arguments, sequences, pauses, results, completion callback, background execution, or cross-device execution. Obsidian must foreground, and context-sensitive commands can still fail if their editor, selection, modal, or plugin state is unavailable.
- Minimum supported Obsidian version remains 1.12.0. Existing Controller settings and note data require no migration.
