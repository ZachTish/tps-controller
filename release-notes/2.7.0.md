# TPS Controller 2.7.0

Calendar sync now keeps lifecycle status values configurable and completes a
validated batch even when unrelated vault activity occurs during planning.
This is a backward-compatible minor release; minimum Obsidian remains 1.12.3.

- Native No-Loss mode leaves occurrences absent from a feed unchanged. When
  No-Loss is disabled and an absent note is archived, the optional
  **Missing-event status value** can set a chosen status; its blank default
  preserves the note's status. Feed absence alone does not prove deletion.
  Explicit cancellations still use **Canceled Status Value**.
- Changing the canceled label updates only Controller-owned cancellations.
  An interrupted replacement retains its ownership record, while user-edited
  statuses are preserved. New active events receive no automatic status.
- Whole-series time changes can now link an occurrence to its former note by
  the exact source identity and prior recurrence clock, then apply the existing
  keep-history choice and previous/current property actions. Ambiguous
  same-day matches and detached exceptions fail closed.
- Unchanged owners are removed from the already validated GCM path plan
  without a second asynchronous planning pass. GCM still checks source,
  generation and paths at the write boundary. Non-Markdown asset and folder
  modifications no longer restart the calendar settlement window.

The full versioned `npm test` passed 622 tests with three existing skips and
zero failures. TypeScript and the separate final `npm run build` passed. The
stable build deployed to the isolated Obsidian Plugin Test Vault; a targeted
plugin reload reported 2.7.0, the new status control appeared on Calendar
rules, and runtime artifacts matched the final build. The test vault has no
external calendar feed, so a live provider sync was not run there. Focused
regressions cover status ownership, recurring master shifts, daylight-saving
time, no-op operation counts, interrupted runs, stale GCM plans and unrelated
asset events. The production vault was not given this plugin build.

Limits: changed provider UIDs, ambiguous same-day lineage and locally edited
untracked schedules cannot be safely joined; they remain unmatched. Inferred
absence remains unchanged with No-Loss on. Tested in the test vault and ready
for the user's BRAT pull; publication does not install it in production.
