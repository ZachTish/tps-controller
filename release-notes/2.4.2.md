# 2.4.2

Patch: restore calendar imports when unrelated native records have invalid identities.

Unrelated incomplete records previously blocked the entire calendar reconciliation snapshot, preventing missing events from being created. GCM now offers `conflictAwareSnapshots` with explicit excluded-owner diagnostics. Controller 2.4.2 uses those diagnostics to isolate unrelated records while rejecting calendar identity, kind, legacy ownership, schedule-stamp and unreadable/unknown identity conflicts. Conflicting IDs remain globally reserved and exact write preflight remains mandatory. Existing strict snapshot/list callers retain their behavior.

Install Controller **2.4.2** and GCM **3.2.0** together for recovery. No settings/default changes or automatic migration of unrelated notes. Controller remains compatible with older GCM's strict behavior. GCM API v6 gains an optional capability; no existing API is removed.

Validation: 575 passing tests, three existing optional comparison skips; 100 focused native-calendar checks. TypeScript and the separate final production build passed and deployed only to Obsidian Plugin Test Vault. Named-vault CLI reload and installed Controller/GCM QA verified one create beside an incomplete unrelated record, zero repeat creates with unchanged bytes, and zero writes when a duplicate calendar owner exists. The unrelated record stayed byte-identical. Fixtures were archived from Inbox; settings hashes and disabled outbound automation were preserved.

Minimum Obsidian: **1.12.3**. Tested in the test vault and ready for the user's BRAT pull; publication is not production installation or user acceptance. Malformed YAML, unreadable source, and relevant calendar conflicts remain conservative blockers. Physical iPhone and live-provider writes are not part of release acceptance.
