# TPS Controller 3.1.2 — Confirm reminder completion

Backward-compatible patch; minimum Obsidian 1.12.3.

## Changes

- Reminder status actions no longer report success when GCM returns zero after
  cancellation, a safety refusal or a failed write.
- Genuine already-applied status changes remain successful: zero is confirmed
  from the authored Markdown of the exact current file, not cached metadata or
  another note occupying its former path. Positive committed writes add no reads.
- Direct Complete and the GCM status/frontmatter routes use the same result check.
  Failures propagate without another writer, retries, repair or deduplication.
- Signed reminder projection replaces the candidate's existing cached body read
  with one fresh read, using its frontmatter consistently for status, schedule,
  title and tags. Completion and reopening no longer wait for stale metadata.
  Source read/parse/identity failures refuse publication and retain the exact
  last-good schedule/audit rather than publish stale data or a false empty state.
  Discovery is still metadata-selected; an entirely new schedule needs its
  ordinary metadata event. Display-only reads stay cached and retain legacy
  best-effort behavior when source content cannot be read or parsed.
- Includes the native Mac refresh invalidation and serialized publication drain
  from installed local 3.1.1, which was not previously published on GitHub. Its
  content-free authenticated loopback signal queues the existing TishOS app's
  authorized vault refresh; it is not an upload acknowledgement or a CloudKit
  Web Services login. Other platforms retain their existing delivery path.

GCM owns the completion/rename write race that produced duplicate notes; install
its separately validated fix too. This Controller change does not delete, merge
or rewrite pre-existing duplicates. No settings/defaults, schema, identity format
or property-key migration changes. Physical device delivery remains a separate
check; source-fresh projection cannot force a receiving widget/background task.

## Validation status

- Saved completion/source regressions: 32 passed. The initial 13 completion
  checks had 3 passes and 10 failures against the prior runtime. Eleven additional
  freshness checks failed before the source-projection fix.
- Covers awaited completion, rejection, zero/invalid results, stale metadata,
  exact file identity across renames/replacements, fallback avoidance,
  immediate completion/reopening ahead of metadata, removed frontmatter/schedule,
  malformed/scalar/list/read failure refusal, legitimate empty maps, consistent
  source title/tags, and one candidate read/scan across 1,000 unrelated notes.
- Combined reminder and bridge selection: 169 passed, three preserved historical
  comparison skips, zero failures. Includes last-good publication/audit retention
  on projection failure and verified empty replacement after recovery.
- Complete no-deploy declared suite: 673 total, 670 passed, three preserved
  historical-comparison skips, zero failures or cancellations. TypeScript and
  the suite's production bundle build pass.
- Separate native TishOS boundary evidence: 13 selected notification-cancellation
  tests pass in an isolated iPhone simulator with synthetic/mocked notification
  state. This does not establish physical delivery, background refresh latency
  or an installed production fix.
- Mandatory separate final production build: passed. Test-vault deployment and
  official Obsidian CLI plugin reload/version checks confirmed Controller 3.1.2
  and GCM 7.3.2. All four installed Controller runtime artifact hashes match the
  standalone build.
- Installed Test-vault verification: two unique synthetic fixtures completed
  through the actual `Controller.completeItemFromNativeNotification` route,
  GCM status setter and filename rename. Each changed six reminder triggers to
  zero, retained exactly one note, and preserved its body.
- Reopening and stale-write race verification: a held asynchronous GCM write
  rejected after Obsidian's core `processFrontMatter` saved a newer completion.
  The stale mutator ran once; the completion date and body remained intact and
  the reminder projection stayed at zero triggers.
- The synthetic fixtures were archived after passing. Test settings were cloned
  in memory without data.json writes or external delivery; both Controller and
  GCM data.json hashes remained unchanged. GCM's recurrence-session lifecycle
  did change, so this does not establish that all runtime state was unchanged.
- Test-vault validated; BRAT handoff, not a production installation. See
  [GitHub releases](https://github.com/ZachTish/tps-controller/releases) for
  publication status.

The saved focused regression tests use in-memory notes only. Installed runtime
checks use uniquely identified synthetic files in the Test Vault, not production
notes. No physical-device delivery or production installation is implied.
