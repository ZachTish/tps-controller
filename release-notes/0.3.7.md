# TPS Controller 0.3.7

TPS Controller `0.3.7` is a backward-compatible S3 bucket-archive reliability and performance patch. Completed cleanup runs now persist their cadence, and overlapping manual, startup, or scheduled callers share one physical archive pass.

## Changes

- Update the live `bucketArchiveLastRunAt` setting before saving, rather than mutating the normalized copy used for execution.
- Join concurrent bucket-archive callers to one active promise, with concise `run:join-active` diagnostics.
- Restore the prior cadence timestamp if settings persistence fails, reject every joined caller, clear the failed flight, and allow a later retry.
- Add an executable compiled-service harness for cadence, guards, save failure, overlap, and retry behavior.

## Preserved behavior

- Controller-only execution, desktop-only loading, disabled-by-default cleanup, configuration and SecretStorage credential guards, orphan delay, final vault-reference recheck, copy-before-delete movement, archive-prefix formatting, and upload-manifest tracking are unchanged.
- `Run S3 Bucket Archive Now`, startup and interval checks, S3 attachment upload, raw-paste and after-command triggers, extension filters, source attachment archiving, and every existing Controller command and setting remain available.
- No setting key, default, command, API, note format, manifest format, or migration changes.
- No fallback, monkeypatch, retry loop, persistent cache, listener, or unsupported Obsidian API is added.

## Before/after evidence

The executable harness compiles and runs both the candidate service and exact released `0.3.6` service source, pinned by SHA-256 `5966bbcacf1440929f16f6eaaa1327006d28076ed1c6dc283dcad20e24de3b20`, against the same synthetic manifest, vault, note, settings, and credential adapters:

- After a successful run at `2,000,000`, exact `0.3.6` leaves the live and saved cadence timestamp at `0`; `0.3.7` persists `2,000,000`.
- A due check one minute into a 60-minute interval adds zero manifest reads/writes, Markdown enumerations, note reads, settings saves, or S3 work in `0.3.7`.
- With two overlapping callers blocked at settings persistence, exact `0.3.6` performs two complete physical passes; `0.3.7` performs one. Manifest reads/writes, vault enumerations, note reads, and settings saves each fall deterministically from `2` to `1`.
- A shared failed save restores the prior timestamp for both callers. After the rejection, the same service starts exactly one fresh physical retry, resolves, and persists only the retry timestamp.

These are deterministic operation counts for the bucket-archive seam. They do not claim that overall Controller, network, S3-provider, or Obsidian latency improves by the same percentage.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- Bucket cleanup remains controller-only, desktop-only, disabled by default, and dependent on valid S3-compatible settings plus device-local credentials.
- This patch does not change the existing copy fallback inside object movement: providers that reject server-side copy can still use the released get-and-put compatibility route before source deletion.
