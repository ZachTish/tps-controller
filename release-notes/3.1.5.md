# TPS Controller 3.1.5

Backward-compatible performance fix removing unused calendar startup and
ordinary-event work on desktop and mobile.

- Remove the eager whole-vault metadata scan and four metadata/create/delete/
  rename listeners owned by native calendar reconciliation. Its only runtime
  consumer is calendar sync, which already replaces that index from a fresh
  authoritative GCM snapshot after fetching feeds and before planning changes.
- Preserve per-sync current-source discovery, configured property mappings,
  identity conflicts, deletion/missing policies, rescheduling/history,
  cancellation ownership, single-flight and snapshot token/revision guards.
- No new cache, watcher, timer, writer, schema, settings migration or UI change.
  Existing settings destinations, controls, commands and layouts remain intact.

Minimum Obsidian: 1.12.3. This is a plugin update, not a TishOS TestFlight build.
Production installation and physical-device acceptance remain separate.

## Validation

- Tests were added first against published 3.1.4. Startup with 10,000 ordinary
  synthetic notes performed one inventory, 10,000 metadata reads, 10,000 GCM
  inspections and four listener registrations. Twenty ordinary create/metadata/
  rename/delete bursts performed 40 metadata reads and 60 inspections. The new
  regressions require zero corresponding calendar service work.
- The focused native-calendar suite passes all 134 checks, including seven new
  checks for startup/event operation counts, first sync with stale/absent cache,
  idle deletion/reschedule, duplicate canonical ownership and concurrent sync.
  The queued stale-cache test now dispatches actual listener lists and proves
  zero event-side work/mutations while current disk properties own the plan.
- Root's isolated installed 3.1.4 service baseline used actual GCM 7.3.11
  inspection with 26 synthetic mappings: both legacy/native modes performed
  the same 10,000-note scan and four registrations. Setup took 367/337 ms in one
  hidden-host synthetic pair. These are not full-startup or physical-device
  input-to-paint measurements. No provider, source read/write, real settings or
  real service state was changed by that probe.
- Final versioned `TPS_NO_DEPLOY=1 npm test`: 687 passed, zero failed, three
  pre-existing historical-comparison skips. TypeScript and the included
  production-mode build passed without deployment. A separate post-documentation
  production-mode build passed, followed by an ordinary TEST-only build/deploy
  and targeted reload verifying Controller 3.1.5 with GCM 7.3.11.
- Installed 3.1.5 constructor verification with the same isolated actual-GCM
  10,000-note workload returned zero inventory/metadata/inspection/listener/
  source/provider/write operations in both calendar modes; twenty ordinary
  metadata events added zero inspections. Inputs, real services and settings
  remained unchanged.
- An actual passive TEST-vault warm Controller-only reload previously made one
  calendar startup inventory and 15,391 metadata lookups. The patched reload
  made neither, with zero counted source reads or mutation calls. One hidden,
  unfocused before/after sample took 211.3/49.7 ms. This is not a cold process
  launch, foreground paint or iPhone/Windows interaction benchmark.
- Standard warm TEST Live Preview navigation passed 13 phases, six tab switches
  and two remounts with real Health macros/activity blocks observed, no reported
  errors or long tasks and zero note-mutation attempts. Settings and active
  workout state were unchanged; three exact synthetic display notes were moved
  to `_archive`, and the original leaf was restored. Reading mode, cold launch,
  active workouts, food edits, provider actions and physical devices are not
  acceptance claims from this hidden-host check.
- Shipped source/runtime artifact hashes matched, Controller runtime `data.json`
  stayed byte-identical, and the existing unrelated dirty README in the prior
  worktree was preserved. Final post-QA documentation is followed by a separate
  ordinary production-mode TEST build before publication.
- Per-sync authoritative discovery retains its existing cost; this is not a
  claim that every UI stall is fixed. No external provider or production vault
  was accessed. Physical mobile acceptance and the user's production BRAT
  installation remain separate.
