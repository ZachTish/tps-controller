# TPS Controller 0.11.8

TishOS can now distinguish an event's true due time from the next future notification in a rolling repeat cadence. Controller publishes one compact signed audit record per selected reminder series with the original event due time and configured repeat interval, cryptographically bound to the existing signed schedule.

The schema-2 schedule itself is unchanged, so older TishOS builds keep scheduling the same one-shot notification occurrences. A compatible TishOS build uses the optional audit only for truthful Reminder Queue grouping and overdue status. Missing, stale, malformed, or tampered audit data is ignored without interrupting notification scheduling.

Live-series fairness also uses the original due time when available. An overdue calendar event therefore keeps its first bounded transport position even when all of its next repeat occurrences are in the future. The existing 128-item transport bound, canonical order, occurrence and series identifiers, fire times, actions, pairing credentials, and reminder settings remain unchanged.

## Validation

- Reminder-engine coverage proves an hours-overdue five-minute rule retains its original due time, exact 300-second cadence, and 128 bounded future occurrences.
- Command-bridge coverage proves the schedule remains schema 2, the audit is schedule-MAC-bound and HMAC-valid, repeated occurrences produce exactly one audit record per series, and 70 overdue series with only future next-fire times all remain represented before repeat extras.
- The complete declared matrix passes `287/290`, with three preserved intentional historical skips and zero failures. TypeScript checking, the production bundle, and BRAT packaging pass.
