# TPS Controller 0.15.0

- New native calendar notes no longer receive a hardcoded public `kind`. Controller tracks the same atomic note through its canonical `tpsId`, independent of an absent or user-edited kind, and requires GCM 1.52.0 / API v6 `calendarTemplateRecords` support before syncing.
- The existing per-calendar **Template** now supplies new native notes' static YAML defaults and Markdown body, including optional text `kind`, workflow status, ordinary tags, and calendar variables. Quote YAML variable values, for example `label: "{{title}}"`; use ordinary text such as `kind: event` for classification; available event variables are defined by the existing event-template variable service. No template means no generated kind. Template controls remain visible in native mode even when an older task-mode selection is saved.
- Feed-owned title, scheduled/end instants, and all-day state remain authoritative. Noncancelled existing notes retain their user status, classification, ordinary tags, and body; they are not re-templated. A new template's workflow status participates in cancellation/restoration without repeated completion resets.
- Template source is read once per sync/path, validated and prepared through GCM before any record batch. Copied technical identity fields are not inherited; event data is expanded inside parsed YAML values so quotes/newlines cannot inject properties. Missing, malformed, rejected, and executable Templater (`<% ... %>`) sources fail closed before mutation. Native import currently supports static Markdown/YAML and existing `{{...}}` calendar variables, not post-create executable Templater scripts.
- The same public properties and exact body are bound to GCM's atomic create plan. Existing canonical IDs remain recognized with custom/absent kind, and positively identified legacy migration retains its safety gates. Existing records are not renamed or reclassified merely for this update, and no extra identity property or setting is added.
- This is a backward-compatible template capability feature with minimum Obsidian 1.12.0. Update GCM first; older providers pause native sync with an explicit update message instead of writing the old hardcoded kind. Final validation and hashes are recorded in `release-notes/0.15.0.md`.
