# TPS Controller 0.3.8

TPS Controller `0.3.8` is a backward-compatible performance and cleanup patch for two-stage archive candidate discovery. It preserves every released archive outcome while removing repeated normalization of already-normalized roots and repeated normalization of the same vault path.

## Changes

- Reuse the source and destination folders normalized by the existing rule resolver.
- Build the source and destination boundary prefixes once per archive pass.
- Normalize each `TFile.path` once, then use that value for both source and nested-destination membership checks.
- Remove the redundant private `isInFolder` normalization wrapper.
- The shipped service shrinks from 224 to 221 lines and from 8,967 to 8,836 source bytes. The production bundle shrinks from 942,700 to 942,595 bytes.

## Preserved behavior

- Empty/equal-folder validation and boundary-safe, case-sensitive folder membership are unchanged.
- Candidate order, original `TFile` identities, relative target paths, nested-destination skips, collision suffixes, folder creation, rename-error handling, moved/skipped counts, cadence persistence, settings saves, and structured logs are unchanged.
- The manual command, scheduled execution, defaults, settings, public API, note and file formats, runtime state, and minimum Obsidian compatibility are unchanged.
- No cache, fallback, monkeypatch, timer, listener, retry, persisted state, migration, or unsupported Obsidian API is added.

## Before/after evidence

- Exact public `0.3.7` is commit `3981a75a24465470f2fa97a7e766848d358fbcfb`; its two-stage archive service is SHA-256 `4b98c46364da2993ffe7e23d72bcbc39ab4cc04d5d3e7990006f5a5fb0bcaa62`.
- The permanent actual-service gate preserves 80 moves, 20 nested-destination skips, the same collision-adjusted first target, the same last target, the same run key, and one settings save. Exact `0.3.7` fails its efficiency budget with 2,365 path normalizations and 1,105 configured-root normalizations; `0.3.8` passes with 1,163 and three.
- Across 500 seeded actual-class differential scenarios, the released and optimized services produced zero result, operation-order, log, folder-creation, collision, rename-failure, save, final-path, or object-identity mismatches.
- On an identical 20,000-file fixture with 19,000 outside files, 500 nested-destination skips, and 500 moves, `normalizePath` calls fell from 43,005 to 21,003 (51.16%) and configured-root normalizations from 21,005 to three (99.986%). Moves, skips, targets, logs, and final state were identical.
- Across 41 alternating prewarmed rounds, median service-seam time fell from 8.483 to 4.521 ms (46.71%) and p95 from 9.047 to 6.600 ms (27.05%).

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- The timing comparison isolates synchronous candidate discovery and path normalization. Filesystem folder creation and file moves can dominate a real archive run, so this is not a claim that an end-to-end run will always be 46% faster.
- Stateful monkeypatches of Obsidian `normalizePath` or side-effectful proxy/getter replacements for `TFile.path` are unsupported and are intentionally not compatibility targets.
- Controller's S3 copy-to-get/put provider fallback remains intact. Removing it without provider-compatibility evidence would remove supported S3-compatible functionality rather than safely simplify the plugin.
