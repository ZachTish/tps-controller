# TPS Controller 2.2.0

Controller can now preserve an event note when an external calendar reschedules its occurrence. In **Calendar rules → Configure a calendar**, enable **Keep old note when externally rescheduled**. This is an opt-in, backward-compatible minor release; existing behavior stays the default.

After the first baseline sync, an external change to the start, end or all-day timing retains the previous note and creates a fresh note for the new schedule. The original body, authored properties, status, identity and path remain; the new note uses current calendar template/defaults. Only the current generation receives later sync, cancellation and missing-event handling. Turning the option off keeps history and resumes updating the current generation in place.

Local note-date edits, title-only changes and cancellation notifications do not create history. Normal feed synchronization can still overwrite local date edits. Existing notes without tracking data establish a baseline on their next sync; earlier reschedules are not inferred. Matching requires a stable provider UID/recurrence identity. Retained history is excluded from automatic legacy matching and duplicate/orphan cleanup. An interrupted retirement can safely resume on the next sync.

## Compatibility and limitations

Minimum Obsidian: **1.12.3**. Requires **Native TPS event records**, TPS GCM native-record mode and nativeRecords API v6 with calendar-template support. Legacy note imports and inline Daily Note tasks retain their existing behavior. Use the designated Controller device for automation; the batch is not a cross-device transaction.

The per-calendar `preserveNotesOnExternalReschedule` boolean defaults false. The reserved `tpsCalendarSync` frontmatter object stores the opaque logical occurrence, last imported timing, and retirement marker. Keep this tracking data intact. It is stripped from template defaults. There are no new commands, routes or disclosures; the native settings toggle has an accessible label.

## Validation and handoff

`npm test`: **523 passed, 3 existing optional skips, zero failures**. Includes 80 native-calendar regressions plus legacy matching/history protection. TypeScript and a separate final production build passed. Deployment targets only **Obsidian Plugin Test Vault**; the final plugin was reloaded and runtime artifact hashes match the build.

UI QA toggled the actual setting on an isolated synthetic calendar and reached its save handler without changing real settings. Real Controller and GCM services created Inbox notes from a synthetic feed, verified no fork for a local date edit, preserved the original body/status/path/ID for an external move, and confirmed repeat-sync idempotence. Unrelated identity-conflict fixtures blocked a whole-vault snapshot, so file-level QA restricted GCM discovery to the synthetic folder; global conflict safeguards are unchanged. Existing filename automation was allowed to settle. Fixtures were archived directly to _archive, settings restored, and Controller's persisted state was unchanged. No outbound feed was called. Physical iPhone acceptance remains user testing.

Tested in the test vault and ready for the user's **BRAT pull**. Production was not inspected, deployed or reloaded. Existing dirty canonical worktrees were preserved; this release was isolated from published main.
