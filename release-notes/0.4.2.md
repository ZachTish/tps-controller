# TPS Controller 0.4.2

Released: 2026-08-14

## Notification-sidebar Daily Note moves

- **Move task** in the notification sidebar's reminder action and target-note picker now requests TPS Global Context Menu Task API v3 with `sourcePolicy: configured-daily-note` and strict `exact-or-identity` resolution.
- For a cross-file move from a recognized Daily Note, GCM's own Daily Note move setting decides whether to retain a migrated source record or remove the source block. This source policy is independent of GCM's Daily Note schedule-inheritance setting. Other source notes keep the ordinary remove-source move behavior.
- Controller identifies this direct interaction with the explicit user cause `{ kind: "user", sourcePluginId: "tps-controller", surface: "reminder-modal" }`. When GCM item history is enabled, GCM owns the resulting local history event; Controller does not create a parallel history store.
- The source note remains excluded from the destination picker. Stale or ambiguous references, rejected or partial writes, and thrown failures remain non-successes and keep the reminder row visible.

## Compatibility and migration

- TPS Global Context Menu Task API v3 is required for notification-sidebar task moves. Missing or older versions fail closed before Controller calls `tasks.move`, show the existing update notice, and cannot accidentally interpret the new policy as a legacy remove-source request.
- Other Controller/GCM integrations keep their existing compatibility behavior.
- Controller's hidden cross-device sync-request file now uses adapter-backed reads and atomic writes, so plugin reload no longer races an unindexed existing file and raises an unhandled `File already exists` error. Request merge and acknowledgement behavior is unchanged.
- This is a backward-compatible patch with no Controller setting, stored-data, or note-schema migration.
- Minimum supported Obsidian version remains 1.12.0.
