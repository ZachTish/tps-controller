# 2.4.3

Patch: exclude unchanged records from calendar write batches and preserve existing archive timestamps.

The complete identity/path preflight still runs. Controller then removes identity entries whose ID, properties and destination are unchanged, replans remaining writes against the same snapshot, and requires identical approved destinations. A settled repeat sync performs no write batch. New events do not replay every unchanged calendar owner. Already archived missing events retain their original archive date.

This reduces full-batch interruptions from unrelated vault writers and automatic filename rules. It does not disable those services or ignore real changes during a write; conflicting/stale batches still stop safely and retry on a later sync. No settings/default/schema changes. GCM API v6 remains supported; GCM 3.2.0+ is required for the separate unrelated-conflict recovery in 2.4.2.

Validation: 578 passing full-suite checks, three existing optional comparison skips, zero failures; 103 focused native-calendar checks. TypeScript and the separate final production build passed. Test-vault CLI reload with Controller 2.4.3 and GCM 3.2.1 verified initial creation, zero write batches on a settled repeat, a single-create batch beside an unchanged owner, preservation of an unrelated invalid note, and duplicate calendar conflict rejection. Fixtures were archived directly from Inbox, settings stayed unchanged, and outbound automation stayed disabled.

Minimum Obsidian: 1.12.3. Tested in Obsidian Plugin Test Vault and ready for a BRAT pull. This patch has not been installed or accepted in production. Physical iPhone behavior has not been exercised.
