# 0.10.0

TPS Controller task-mode calendar sync now creates tasks with native linked titles and can move a rescheduled task to its new Daily Note.

- Every newly created calendar task displays `[[linked note|Event title]]` rather than plain title text.
- Each calendar can link recurring tasks either to one note per scheduled day or one shared series note, under a configurable folder.
- A Daily Note task rescheduled to a different local day moves to that day's canonical Daily Note with its indented child block, updated schedule, and updated association metadata.
- Task-mode feeds no longer validate or reject an obsolete hidden note-mode folder before routing to the Daily Note task writer. Calendars switched from note mode to task mode therefore keep creating tasks even when their saved legacy note folder is protected, such as `_archive/...`.
- The move is target-first and fail-closed: exact source confirmation is required, target insertion is rolled back after a concurrent source edit, and duplicate/ambiguous identities are never guessed.
- Ordinary events whose legacy occurrence ID changed with their start time can be recovered only through one unique source-scoped UID. Multiple recurring occurrences with the same UID stay ambiguous.
- A fixed single-task-note destination continues to update in place. Existing tasks are not bulk rewritten; they adopt linked-title metadata only during a later safe reconciliation.

This is a backward-compatible minor release with two additive per-calendar settings. Minimum supported Obsidian remains 1.12.0. Linked note targets use a stable opaque suffix, and Controller creates only their folders; the linked note is created by Obsidian when the user opens an unresolved link.
