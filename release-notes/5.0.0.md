# TPS Controller 5.0.0 — retire background integration owners

Controller no longer automatically evaluates/delivers reminders, publishes command catalogs or Apple notification schedules, imports calendars, runs Finance relay or attachment synchronization, sweeps Sync conflicts, schedules archives, maintains parents, or periodically reloads Obsidian. This is an intentional major behavior change, not an opt-out mode or replacement transport.

Existing notes, saved rules/feeds, credentials, pairing data, pending work, mailbox files and historical state are preserved. This release does not configure or verify TishOS replacements. Known legacy app command/pairing/notification protocol callbacks explicitly report retirement and perform no action.

## What remains

Explicit Note Rules preview/application, manual Two-Stage Archive, retained connection-settings handoffs, and manual Notifications review with status/completion/snooze actions. Notifications refreshes when opened, when Refresh is pressed, and after its own actions. Automatic sidebar refreshes are removed. Selection uses indexed metadata and may briefly reflect stale metadata; explicit mutations retain authoritative-source/identity checks.

## Removed work

- Reminder/catalog 60-second refresh, calendar request polling, Finance/attachment polling, conflict startup fallback/listeners, scheduled archive timer, and periodic reload owner.
- Attachment owner’s four file listeners and automatic transfers; conflict owner’s four event subscriptions.
- Sidebar’s 30-second timer and five subscriptions.
- Unreachable calendar parser/writers/reschedule helpers, old inline readers, transport/signing contracts, generated-state publishers, and `ical.js` dependency.
- Runtime source: 115 lines added, 24,308 removed; net **24,193 lines removed**. Tests/docs/generated bundles excluded. No new scheduler, mailbox, cache, or repair layer.

Startup now also checks its existing unload flag after asynchronous settings initialization. A test reproduced late owner registration before this one-line fix; it no longer occurs.

## Validation

- **178 tests passed**, zero failures; three optional historical comparison tests skipped. TypeScript, separate final production build, test-vault deployment, manifest refresh and plugin reload passed.
- Retirement tests invoke 400 legacy callbacks with no app/state access or mutation; sidebar tests retain explicit refresh and block post-close evaluation. Current-source completion/snooze, manual archive, settings-merge and identity checks remain covered.
- Installed Overdue fixture: same three eligible notes from five candidates; Controller body reads fell from five to zero, inventory remained one, writer attempts zero. Final 5.0.0 native UI showed Notifications' empty state and the reminder-retirement message; all seven settings destinations had prior no-write/provider inspection.
- Combined cleaned TPS foreground measurements, five samples each: startup median 6084.7 ms versus 6066.2 ms; 20-note navigation median 838.9 ms versus 897.2 ms. These are suite-level test-vault samples, not Controller-only attribution or production/mobile performance claims. Suite idle, typing, Sync-burst and settings checks observed zero TPS maintenance writes; core saves/indexing were counted separately.

Requires **Obsidian 1.12.3+**. Physical iPhone acceptance remains unverified. Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. Production is unchanged. Other TPS cleanup releases are separate.

Downgrading can reactivate the older background owners using preserved configuration/state. Review those controls before enabling the previous release. Installing or rolling back the plugin does not restore notes.
