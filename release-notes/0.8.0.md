# TPS Controller 0.8.0

Released: 2026-08-17

## Device-local periodic Controller reload

- Adds **Reload Controller every 15 minutes** under Advanced → Troubleshooting for always-on desktop Controller devices that need to load plugin settings after those settings sync from another device.
- The preference is vault-scoped local storage, defaults off, and is deliberately absent from synced Controller settings. It runs only while this device is desktop, locally assigned the Controller role, and still opted in.
- Each cycle warns one minute before reloading. At the 15-minute boundary Controller drains previously requested settings writes, flushes local reminder state, saves every open public text-file view and the workspace layout, rechecks eligibility, and invokes Obsidian's built-in app reload command.
- Enabling never causes an immediate reload. Disable, role changes, mobile/passive behavior, unload, stale callbacks, and stale asynchronous preflights cancel safely. Failures and rejected/unavailable commands wait for a new full cycle.
- Reload preflight never calls `saveSettings()`, so it cannot rewrite the current in-memory Controller object over a newer synced settings payload. The removed raw browser fallback remains removed.

## Safety and limitations

- Reloading can reset undo history, interrupt active automation, or discard another plugin's unsaved in-memory state; the settings description and one-minute warning make that consequence explicit.
- This reloads the Obsidian app window. It does not relaunch a quit/crashed process, force a sync provider to complete, or guarantee that a remote settings update arrived before the current cycle.
- `app:reload` is an internal Obsidian command behind one typed, fail-closed adapter because Obsidian exposes no public whole-app reload API. If that command is unavailable, Controller does not fall back to `window.location.reload()`.
- No synced setting, reminder state, note data, or Controller automation rule is migrated. Minimum supported Obsidian remains 1.12.0.
