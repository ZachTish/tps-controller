# TPS Controller 3.1.4

Backward-compatible performance fix for background reminder work that can delay
clicks, taps and other Obsidian interactions on desktop and mobile.

- Reuse GCM's existing conflict-aware authoritative snapshot. One conflicting
  note no longer forces re-inspection of every other note. Conflicted paths are
  still inspected individually; invalid conflict IDs are never trusted.
- Stop resolving the retired inline-task inheritance policy for whole-note
  reminders. Current-source reads, tags and completion/reopening checks remain.
- Preserve configured event fields, duplicate/completed/deleted ownership,
  legacy matching and older/failed API behavior. No new cache, background job,
  note writer, settings migration or weakened cancellation guard.

Minimum Obsidian: 1.12.3. This is a plugin update, not a TishOS TestFlight build.

## Validation

- Final versioned `TPS_NO_DEPLOY=1 npm test`: 680 passed, zero failed,
  three pre-existing historical skips. Separate production-mode build passed
  and deployed only to Obsidian Plugin Test Vault; named plugin reload verified
  Controller 3.1.4 with GCM 7.3.6.
- Repeated 4,001-note synthetic matching: 12,003 individual inspections become
  zero. Conflicted paths retain inspection and all matching sets remain equal.
  Whole-note target regression removes 480 unused policy lookups while retaining
  320 fresh and 160 cached source reads across its candidate cases.
- Installed test vault, approximately 13,900 notes and 2,550 synthetic record
  conflicts: old warm matching took 175.4/211.3 ms with 13,895 inspections each;
  the paired patches took 122.4/127.8 ms with 2,550 inspections and zero source
  rereads each. Every matching set had the same digest before and after. These
  are hidden/background-window service timings, not input-to-paint timings or
  measurements on Windows/iPhone. Cold indexing still reads current source:
  first use after GCM reload took 4.63 s with 13,897 reads in this large test vault.
- Installed integration used actual Complete/status mutation routes on two
  isolated synthetic notes. The initial 14 projected alerts became zero after
  completion plus duplicate deletion; zero persisted after settling and an
  unrelated edit. Reopening restored legitimate reminders and completing again
  removed them. Checklist/body content was preserved. This checks projection,
  not delivery or cancellation on Apple's notification service.
- Fixture notes were retained in `_archive`; no production notes were changed,
  outbound delivery was not invoked, and both plugin settings files remained
  byte-identical. No physical device was installed or controlled.

Install both Controller 3.1.4 and GCM 7.3.6 through BRAT for the full performance
improvement; GCM 7.3.6 bounds the existing conflict-diagnostic work. No settings
or schema migration is required. These are tested public plugin releases ready
for the user's BRAT pull, not a claim of production installation or that every
possible source of UI delay has been eliminated.
