# TPS Controller 3.1.6

Backward-compatible startup-readiness fix for desktop and mobile.

- Require GCM's published API before Controller accesses private maintenance,
  settings or timer services. Private service construction is not readiness.
- Preserve the existing published-API compatibility fallbacks, method receivers,
  recurrence and parent maintenance. Existing ticks observe later publication
  directly; no new availability state, listener, poller, retry or cache is added.
- Leave Calendar/Notifier lookups, settings, commands and UI unchanged.

Minimum Obsidian: 1.12.3. This is a plugin update, not a TishOS TestFlight build.
Production installation and physical-device acceptance remain separate.

## Validation

- Thirteen actual Controller-method controls were added first against published
  3.1.5: seven passed and six reproduced pre-publication private access/work.
  The scope includes missing/null/false APIs, authority removed after unload,
  disabled/missing plugins, User role, legacy ID, late publication, unchanged
  service receivers/fallbacks, and independent Calendar/Notifier lookups.
- A separate replay composes actual Controller and GCM legacy maintenance methods
  over 1,025 synthetic notes while native setup/history barriers are unresolved.
  Before the guard it made two inventories, 2,050 metadata reads and one modeled
  self-link atomic-writer call without accessing either readiness barrier. The
  current parent-repair route remains a retired no-op. Writer/link/safety and
  host boundaries are synthetic in memory, not real vault mutations or timings.
- After the guard, all thirteen controls pass. The same actual-method replay
  performs zero work while the API is absent, then preserves the two inventories,
  2,050 metadata reads and one modeled writer call on the existing later ticks
  after API publication. This fixes readiness ownership, not the cost of
  intentionally enabled maintenance once GCM is ready.
- An installed 3.1.5 comparison uses cloned compiled Controller methods and
  isolated two-note hosts/private receivers while the real Controller remains
  passive. Four of eight readiness controls fail: absent/null/false APIs each
  invoke one inventory, two metadata lookups, recurrence/reconciliation/self-link
  callbacks and eight private-property accesses; late publication also does early
  work. The probe preserves live methods, enabled state, settings/data and all
  eight active plugin artifacts. It does not invoke real automation or establish
  writer duration, foreground rendering or physical-device latency.
- Node 24 versioned `TPS_NO_DEPLOY=1 npm test` passes all 700 checks, with zero
  failures/cancellations and three pre-existing historical-comparison skips.
  TypeScript and its included production-mode build pass. A separate build-only
  `npm run build` also passes, reporting no runtime deployment.
- The three optional checks in `test-notification-open-lifecycle.mjs` were then
  enabled with `TPS_CONTROLLER_NOTIFICATION_COMPARE_ROOT` pointing to a clean,
  read-only TEST worktree of released 0.3.5 commit
  `a8c13dbda82caa95807d4fce912334b8feb9583e`. Its exact overdue-source SHA-256 is
  `6eb91fccf2aff0e35367dbc7cfd1cac81fc2ca818df8c7e9b8e449d5edf5ac04`.
  All five lifecycle checks pass with zero skips, including equivalent output
  with half the scan work, shared lifecycle failures without the redundant
  refresh failure, and the documented narrower post-initial-scan freshness
  window. These are synthetic lifecycle/operation-count controls, not new
  performance claims for this patch. The old runtime was not built or deployed.
- The ordinary build deployed the exact candidate to TEST. A named Controller
  reload confirmed 3.1.6 and preserved all eight active consumers' settings/data,
  enabled state, Controller's passive role and the four artifact hashes.
- The same installed actual-method controls now pass 8/8 versus 4/8 before the
  fix. Missing/null/false APIs, disabled/missing GCM and User role produce zero
  inventories, metadata lookups, private accesses or maintenance callbacks.
  Published and later-published APIs retain the exact existing compatibility
  behavior. Synthetic hosts/receivers do not run real Controller maintenance,
  source reads/writes or providers. TEST was hidden and unfocused; no foreground
  or physical-device timing is claimed.
- Validated in the test vault for the public BRAT release. No production
  installation is claimed.
