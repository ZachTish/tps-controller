# TPS Controller 4.0.0 — Configurable record identity named id

This is a major compatibility release because the canonical record contract or standalone physical-identity default changes. Minimum supported Obsidian: **1.12.3**.

## Behavior

Calendar import/mutations require GCM nativeRecords API7. Canonical envelopes and standalone defaults use `id`; configured physical identities remain owned by GCM. Occurrence ID values, provider references, cancellation ledger, templates, note rules and reminder handle IDs retain their meaning.

## Coordinated rollout

Update Health 5.0.0, Controller 4.0.0, Calendar Base 3.0.0 and Finances 5.0.0 together with GCM 9.0.0. Pause native authoring/imports during a mixed API6/API7 installation; install consumers first, GCM last, reload and confirm API7 readiness before resuming. The combined set requires Obsidian 1.12.3 or newer. Custom API callbacks must use canonical `id`.

Keep the existing physical key until its explicit migration is reviewed and confirmed. Upgrading does not automatically rename notes. Standalone old-primary notes require migration or the retained GCM profile. Resolve Health identity/business-field conflicts before upgrading; conflicting saved mappings intentionally fail closed. Downgrading alone does not reverse a physical migration.

The plugin settings destinations, defaults outside identity, disclosures and mobile layout stay unchanged. No new watcher, poller, background migration, normalization-on-open, repair or deduplication layer is added. External IDs and opaque identity values are preserved. Intentional old literals remain only decoding, migration or conflict-protection evidence.
