# TPS Controller 0.3.5

TPS Controller `0.3.5` is a backward-compatible calendar vault-index performance and reliability patch. One physical sync now compiles its configured scan roots once instead of rebuilding and renormalizing the complete root list for every Markdown file and duplicate identity comparison.

## Changes

- One invocation-local root snapshot now owns the no-root guard, sync diagnostics, vault-index scope checks, and duplicate preference.
- Every file's scope is calculated once and stored only on its transient in-memory index record.
- A root setting changed during an active scan applies coherently on the next sync instead of producing a partially old/partially new index.
- No persistent cache, invalidation listener, observer, retry, fallback, monkeypatch, unsupported Obsidian API, setting, command, or data schema was added.

## Preserved behavior

- Controller still scans every non-`.trash` Markdown file for canonical `externalId`, source-scoped legacy event ID, UID/start, event URL, title/day, and inline-task identity.
- Moved, out-of-scope, ignored, and archived notes remain available for identity reuse so Controller does not recreate existing events.
- Configured roots and ignore patterns still affect only note-level orphan quarantine/archive/delete eligibility.
- Inline calendar tasks never enter note-level orphan cleanup.
- Root normalization, empty-root whole-vault behavior, case-sensitive exact/descendant boundaries, vault traversal order, first-wins identity maps, and the released archive-versus-scope duplicate truth table remain unchanged.
- All existing settings, commands, logs, workspace events, API methods, stored data, calendar creation/reconciliation, cancellation, orphan safeguards, reminder behavior, and S3/two-stage archive automation remain available.

## Before/after evidence

The compiled real-service harness ran the exact released `0.3.4` source and the candidate against the same 20,000-file, 40-root fixture for five warmups and 35 measured iterations:

- Root-set builds per index invocation: `20,001` to `1`.
- Configured-root normalizations per index invocation: `800,040` to `40`.
- Median index time: `369.567 ms` to `97.780 ms` (`73.5%` reduction).
- p95 index time: `374.750 ms` to `105.203 ms` (`71.9%` reduction).

These measurements isolate the vault-index scope-classification seam. They do not include network fetch, note mutation, provider parsing, or the complete calendar-sync duration.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- Documented identity recovery routes are intentionally retained; removing them would make moved or legacy event notes eligible for duplicate recreation.
- Scope membership still performs simple exact/descendant comparisons across the invocation-local roots. This patch deliberately avoids a persistent cache or more complex index.
