# TPS Controller 2.6.3

Reminder discovery now respects the configured inline-task scope before reading
note bodies. Notes-only mode, including Follow GCM with Atomic note mode or an
unavailable GCM, no longer reads unrelated notes to find tasks that the target
builder would discard. This is a backward-compatible performance patch.

Discovery and target construction share the existing runtime-policy module.
Frontmatter reminder candidates still read current content for prose tags and
retain existing reminder evaluation. Scheduled/all inline modes, Follow GCM with
Atomic line mode, and legacy missing-mode behavior retain source parsing. Empty
or stale task metadata cannot suppress enabled inline reminders. No setting,
default, cache, observer, timer, migration or write behavior is added or changed.
External event identity matching retains its independent full-vault checks.

The regression fixture contains 1,000 ordinary notes, one inline task and one
frontmatter reminder. Each notes-only discovery makes zero body reads instead of
1,001; three repeated runs stay at zero. Enabled inline modes retain all 1,001
reads and find the task, including with deliberately stale empty task metadata.
Actual frontmatter candidates retain current body tags. Counts apply to candidate
discovery, not the complete reminder projection or overall vault performance.

Validation: the full versioned `npm test` passed 602 tests with three existing
optional historical-comparison skips and zero failures. TypeScript and the
separate final production-mode build passed and deployed only to the isolated
Obsidian Plugin Test Vault. A vault-guarded disable/load-manifest/enable reload
verified the installed version as 2.6.3.
Its actual compiled candidate-discovery implementation, using a synthetic app
facade, reproduced zero body reads for notes-only and Follow GCM/Atomic note
modes, compared with 1,001 reads per mode in installed 2.6.2. Scheduled inline
mode retained 1,001 reads and both reminder candidates; frontmatter candidates
remained present in all modes. The final build preserved the tested artifact
bytes and independent runtime settings. This is an operation-count check of
candidate discovery, not end-to-end reminder delivery latency.

No production vault, credentials, pairing, outbound provider or real notes were
changed for these synthetic checks. Minimum Obsidian remains 1.12.3. Physical
iPhone and production latency are unverified. Tested in the test vault and ready
for the user's BRAT pull; this release is not installed in production by this work.
