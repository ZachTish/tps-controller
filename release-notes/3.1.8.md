# TPS Controller 3.1.8

Reminder publication rejects already-excluded notes from settled metadata before reading their bodies. Unknown and qualifying sources still receive current-source verification; repeating past reminders retain configured behavior. Unrelated note edits refresh the schedule without rebuilding the command catalog. Commands, pairing, alerts, snooze, cancellation and the last valid schedule remain supported.

With TPS GCM 8.1.0, notification matching uses its read-only settled indexed snapshot; calendar mutations retain authoritative snapshots. Older GCM retains the prior authority path. Unready or failed source evidence preserves the last signed schedule. Service-owned relay/state changes do not invalidate reminder notes or extend calendar settlement after initial readiness.

Removed obsolete parent-maintenance scans/timers. Calendar requests distinguish deferred work from completed work, settings migration persists once, and shutdown invalidates producers before awaiting drainage. GCM's optional identityApplyCancellation capability also stops later calendar batch entries after unload, preserving the committed prefix.

This is a backward-compatible patch with no new setting or schema migration, scheduler, cache, mailbox or delivery system. The existing attachmentSync default now persists only when genuinely missing. Minimum Obsidian: 1.12.3. The existing 60-second command refresh remains for command discovery.

Actual 4,049-note policy/candidate fixture: 4,048 prior source reads become two, including a genuine unknown-metadata reminder and a newly excluded current-source note; zero mutation attempts. Initial note bursts produce zero notification debounce churn, and unrelated note refreshes rebuild zero command catalogs. A valid metadata map without a rule key is known absent; unknown or malformed evidence remains conservative. Current source owns exclusions and parsing, so metadata never authorizes an overwrite.

Final versioned source validation passes 748/748 checks with zero failures, cancellations or skips using Node 24.19.0 and the exact released 0.3.5 notification-open reference (a8c13dbda82caa95807d4fce912334b8feb9583e). TypeScript and the separate build-only gate pass. The ordinary build deployed to TEST; targeted reload loaded Controller 3.1.8 with GCM 8.1.0, and all four artifacts match the installed bytes.

Installed actual-class/API QA passes against bounded memory-only sources: the reminder engine performs one inventory, 8,098 metadata lookups, two raw reads and one occurrence with zero writes or authority snapshots. Pending indexed readiness rejects before further source work. One hundred queries of the actual GCM indexed API perform zero raw/cached reads, inventories, writes or authority refreshes and return no mutation token. Time-tracking fixtures cover configured-key discovery, repeated scans, same-stat/stale-metadata changes, rename/delete, malformed-source refusal and disposal. Vault/GCM/provider boundaries are synthetic where stated; no real notes, sessions, providers or settings were changed by those fixtures.

All eight active consumers remain enabled in TEST with outbound automation off. Controller's settings match the exact baseline after excluding the intended one-time attachmentSync default; ordinary sync-request runtime state is allowed to change. GCM, Health, Finance, Calendar and Linter state remain byte-unchanged; Navigator only acknowledges its version update.
