# TPS Controller 1.0.0 — attachment sync for device testing

This release replaces public S3 attachment offloading with encrypted Google Cloud Storage sync. Full local attachment copies remain on each device. Additions, edits, renames, and deletions reconcile independently of the Controller/User role; ordinary note links remain local. Native Markdown, canvases, bases, Obsidian configuration, hidden/internal content, dependencies, and development folders are excluded.

The major version reflects retirement of the public-link uploader and source archiver. Minimum Obsidian is 1.12.3 for binary append support. The existing connection and secret references migrate to disabled versioned attachmentSync settings; enrollment is explicit on each device. Old upload shortcuts now run Sync now. Bucket-archive shortcuts explain their retirement, and queued source-archive requests no longer move files.

The implementation includes AES-256-GCM encrypted catalogs and 8 MiB chunks, generation-conditional catalog commits, newest-recorded-change ordering, durable deletion records, leased upload reservations, exact obsolete-chunk cleanup, local IndexedDB journals, resumable bounded downloads, trash-aware replacement, path/collision checks, and guarded legacy restoration. No conflict copies or Controller-managed cloud history are retained. Concurrent ordering depends on device clocks; edits after observing a revision advance the logical clock. Closed-app deletion time is its detection time.

Validation on 2026-09-10: full npm test: 447 total, 444 passed, 3 existing reminder skips, zero failures; TypeScript clean; final separate npm run build deployed to Obsidian Plugin Test Vault; explicit Controller reload confirmed 1.0.0 with attachment sync and core Obsidian Sync disabled. Full mobile bundle loads without Node modules, Buffer, or process. Desktop and simulated 390px phone settings were visually inspected, all 15 attachment settings/action rows inventoried, selected-route focus/aria state checked, and unrelated settings destinations rendered. UI emulation/window overrides were restored.

The actual desktop Obsidian diagnostic passed a 500,000,000-byte generated MP4 and a 500,000,000-byte non-media file, encrypted roundtrips, durable checkpoint recovery, hidden staging reads, and exact persisted-file SHA-256 comparisons. Chunk maxima were 8,388,608 plaintext bytes and 8,388,637 encrypted bytes. No cloud endpoint was configured; this result does not satisfy mobile or cloud feasibility. Fixture/report location: Inbox/Controller Attachment Sync QA/Latest diagnostic.json, completed files archived under _archive/Controller Attachment Sync QA.

This public BRAT-compatible release is provided for user/device testing. Actual iPhone AND iPad transfers for both 500 MB file types through an isolated GCS collection remain unverified, including both directions, interruption/suspension/resume, final hashes, observed process memory, and cross-device convergence. Physical devices and isolated test credentials were unavailable during development. A failed byte-range check stops the transfer; there is no whole-file mobile fallback. Test-vault and desktop validation do not certify mobile or real GCS operation. Production installation remains the user's BRAT handoff; the agent did not access or install into production.

To test: update `ZachTish/tps-controller` through BRAT to numeric version **1.0.0** (minimum Obsidian **1.12.3**). Attachment sync starts disabled. Configure the isolated GCS destination and device-local credentials, create the encrypted collection on the first device, import its recovery key on the other devices, and explicitly join each device. Run **Controller → Automations → Sync attachments → Device verification → Run diagnostic** on iPhone and iPad. Keep the reports and separately observe process memory and true OS suspension recovery.

GCS versioning can be queried through the XML connection; soft-delete and retention remain unknown and require separate Google Cloud inspection. Controller does not change bucket policies. Keys cannot be recovered if lost; encryption-key rotation is not implemented. Local trash uses the device's configured behavior. The encrypted catalog is bounded to 16 MiB; durable tombstones and abandoned-upload cleanup markers grow over time. The public adapter cannot provide an atomic filesystem compare-and-swap against unrelated OS writers, so mutation guards minimize rather than eliminate that filesystem race. User-operated Obsidian Sync storage reclamation is separate from disabling attachment syncing.
