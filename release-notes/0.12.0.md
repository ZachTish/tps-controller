# TPS Controller 0.12.0

Native Markdown calendar records now use the TPS system's one standard unique identifier, `tpsId`, instead of persisting a second layer of calendar/source/UID/occurrence keys.

- New calendar records persist no `calendarId`, `calendarSourceId`, `calendarUid`, `calendarOccurrenceId`, `calendarOccurrenceIdentity`, `calendarOccurrenceKey`, `calendarRecurring`, `calendarSyncState`, `calendarMissingAt`, `associatedNotePath`, or `associatedNoteStrategy` fields. New records also do not invent an `associatedNote`.
- A canonical `calendar:v1:...` `tpsId` derives from the saved calendar configuration and logical occurrence with source-keyed SHA-256 digests. Raw feed URLs and UIDs are not stored or recoverable from the ID. The source scope still permits safe feed-specific missing-event handling from the ID alone.
- Existing Controller-owned records migrate on reconciliation while preserving body, ordinary user tags, business properties, blank or user-selected status on non-cancelled records, and a genuine non-self `associatedNote`; unresolved path-only relationships become that surviving link. Manual calendar notes with no positive Controller legacy identity evidence remain manual.
- Controller fetches first, freezes calendar settings and an authoritative GCM `{ token, revision, records }` snapshot, previews GCM's ordered create/rename paths, rebuilds path-dependent exact payloads, and submits one locked batch. The plan covers every native-record kind, malformed/blocked evidence, case-insensitive identity and storage-key collisions, exact create/update values, filename suffix reservations, self-links, cleanup, and missing-event archive updates.
- Deterministic or other GCM mutation races reject before the batch starts. A truly external Markdown/Sync change between separate file commits returns a structured committed prefix and failed index; Controller rebuilds authoritative state and converges on a later sync instead of claiming a false rollback. Delayed MetadataCache events are ignored throughout the authoritative sync window.
- Missing legacy calendar configuration IDs are backfilled with Controller's exact historical normalized-URL fallback, allowing their old records to map correctly. Reminder deduplication uses authoritative GCM handles when MetadataCache is delayed and retains legacy fallbacks only for transition compatibility.
- Conflict-style calendar filenames such as a legitimate GCM-allocated `Event (2).md` now wait for metadata readiness and are rechecked when MetadataCache changes instead of being archived as a Sync duplicate.

Native calendar storage requires TPS Global Context Menu 1.48.0 and nativeRecords API v5. Legacy task-line calendar mode, reminder settings/rules, commands, and note schemas outside native calendar records are unchanged. Minimum supported Obsidian remains 1.12.0.
