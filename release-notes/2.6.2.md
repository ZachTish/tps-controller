# TPS Controller 2.6.2

Notification publication now serializes each candidate key once and hashes audit identities once per distinct reminder series. Previously it rehashed each repeated occurrence, even when only 128 notifications could be published. This is a backward-compatible performance patch.

Every occurrence still participates in the selected series' due-time/cadence validation, including occurrences excluded from the published 128. Chronological/UTF-8 order, duplicate handling, live-series fairness, signatures, repeat cadence, horizon, refresh triggers and completion/snooze behavior are preserved. No settings, persisted caches, watchers, repairs or note migrations are added.

Installed test-vault desktop benchmark with 21,504 synthetic candidates:

| Operation | 2.6.1 | 2.6.2 |
| --- | ---: | ---: |
| Select notification items | 56.8 ms | 46.6 ms |
| Build series audit | 588.9 ms | 10.1 ms |

Both versions produced the identical 128 items and one series: output SHA-256 `c1d710195939789322ad5c5ca725b37220f5eb9f2f1ec286776647d2c910cce2`. This is one before/after sample, not a general device guarantee. Install GCM 3.5.1 as well: it removes repeated property resolution from event matching and Navigator presentation. Controller still rebuilds its event index and projects up to 128 repeats per reminder; this patch does not introduce a new invalidation scheme or change policy.

Validation: 593 declared-suite tests passed; three existing optional historical-comparison tests were skipped because no comparison checkout was configured. The new large-fixture regression verifies exact prior output, duplicate handling and inconsistent unselected repeats. TypeScript and the separate production build passed, with test-only deployment and targeted reload of 2.6.2. Benchmark builders were called directly without pairing, external providers or outbound publication. The clock override was restored and runtime settings stayed byte-identical. Minimum Obsidian 1.12.3; physical iPhone timing remains unverified.

Tested in Obsidian Plugin Test Vault and ready for the user's BRAT pull. No production artifacts, notes or settings were changed; production installation and acceptance are separate.
