# TPS Controller 0.3.3

TPS Controller `0.3.3` is a backward-compatible calendar-sync concurrency reliability and performance patch. Overlapping sync requests now join one physical run instead of allowing later wrappers to report completion before reconciliation has finished.

## Changes

- Startup, interval, manual, settings, and cross-device callers share one active calendar-sync promise.
- The first caller's force and historical-backfill options own an overlapping flight; no second run is queued.
- Joined callers settle with the same success or failure, and the flight clears after success, failure, or a readiness skip so a later request can run normally.
- Calendar sync start/completion events and recurrence maintenance now run once per physical reconciliation.
- Existing AutoCreate's lower-level defensive guard remains in place.
- Calendar sources, the valid Calendar-plugin settings fallback, event creation and reconciliation, settings, and stored data are unchanged.

## Before/after evidence

- With 100 callers overlapping one blocked physical sync, released `0.3.2` executed the wrapper 100 times, called AutoCreate 100 times (99 were discarded by its inner guard), emitted 100 start events, ran 99 premature completion-maintenance callbacks, and emitted 99 premature completed events before the physical run was released.
- `0.3.3` performs one wrapper/configuration pass, one AutoCreate call, one start event, and zero completion work while the physical run is blocked. After release it runs maintenance and emits completion exactly once.
- Deterministic regressions also cover first-call option ownership, synchronous event-listener re-entry, joined physical failures, completion-maintenance failures, readiness skips, and a fresh retry after every settlement path.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- A role stop or plugin unload still does not cancel a physical calendar reconciliation already in progress, matching released behavior.
- Role restart/config mutation during an already active reconciliation is a separate pre-existing lifecycle concern and is not claimed as fixed here.
